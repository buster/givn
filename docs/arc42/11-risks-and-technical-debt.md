# 11. Risks and Technical Debt

## 11.1 Risks

| ID | Risk | Likelihood | Impact | Mitigation |
| --- | --- | --- | --- | --- |
| R-1 | The `gherkin` crate's AST does not expose enough position info to losslessly merge + strip tags while preserving formatting. | Medium | High | **Resolved (Phase 3):** merge operates on a line-based text model, not a full AST rewrite. This preserves formatting and comments correctly. |
| R-2 | Overlay/patch semantics for the manifest become ambiguous (deep-merge edge cases). | Medium | Medium | **Resolved (Phase 2):** overlay rules specified and unit-tested for add/modify/remove/cycle/dangling-requires. |
| R-3 | `serde_yaml_ng` diverges or is itself abandoned. | Low | Medium | Thin wrapper around (de)serialisation; `serde_norway` is a fallback fork. |
| R-4 | Skill/agent conventions shift (the `.agents/skills` convention is emerging, not ratified). | Medium | Low | Templates are ejectable and targets are pluggable; adding/altering a target is cheap. |
| R-5 | Cross-platform static linking (musl, Windows) causes build friction. | Medium | Medium | Use `cargo-dist`; pin toolchains; test in CI before first release. |
| R-6 | Merge corrupts the permanent spec on a partial failure. | Low | High | All-or-nothing archive: validate every precondition before any write; write atomically. |
| R-7 | Scope creep back toward OpenSpec's dropped features (profiles, context stores). | Medium | Medium | Chapter 3.3 non-goals are explicit; keep them out of v1. |
| R-8 | Filesystem-derived state misreads partially-written or manually-edited dirs. | Low | Medium | Derive conservatively; treat ambiguous states as "in progress"; never auto-destroy on inference. |
| R-9 | Path traversal in `--change` parameter (e.g. `--change "../etc"`). | Low | High | **Resolved:** every command that accepts `--change` now validates the id as kebab-case via the shared `resolve_change_dir` helper before constructing any filesystem path. Invalid ids are rejected with a clear error. |
| R-10 | Durable Arc42 chapters become stale, or implementation silently diverges from documented architecture after design-review. | Medium | High | When the `arc42` addon is enabled, completion review independently cross-checks Arc42 facts and affected chapters against `design.md`, `tasks.md`, and implementation evidence; mismatches block sign-off. |
| R-11 | The prompt-layer conformance review is completed superficially or omitted because the binary does not parse architecture facts. | Medium | High | Require `ARC42 CONFORMANCE: CLEAN` and a completed evidence table in the review assets; design-review and the review instructions state that any unresolved row prevents human sign-off. |
| R-12 | Existing projects that previously synced all three agent targets silently narrow to opencode after upgrade, orphaning stale `.agents`/`.claude` files. | Medium | Low | Config default is opencode-only; projects wanting all three add `skills: { targets: [opencode, agents, claude] }`. Addon `disable` still cleans all three targets so stale files can be removed. |
| R-13 | A project merge script succeeds without replacing an old merged report, publishing stale README values. | Medium | High | Archive removes the configured output before running `coverage.merge_command` and rejects a successful command that does not recreate it. |
| R-14 | E2E and non-E2E reports use different scopes or a project script merges counters incorrectly, making badges look authoritative when they are not. | Medium | High | Scripts are project-owned and documented in the README; givn validates both source reports and the fresh merged report, while review maps every instrumented production process and classifies invalid measurement as a fabrication finding. |
| R-15 | A zero branch denominator is rendered as `0%`, implying measured branch coverage where the tool emitted no branches. | High | Medium | Render `n/a` for `branches-valid=0` in the badge and summary, while preserving the raw `0/0` counters. |
| R-16 | Coverage or README updates partially succeed before a later archive gate fails, leaving user content or reports changed. | Low | High | Back up README and configured coverage paths before measurement and restore them together with permanent specs on every coverage error. |
| R-17 | Authors follow different E2E policy wording depending on the entry point used, reintroducing duplicate or under-covered interactions. | Medium | High | Keep the complete policy in the `specs` instruction; scan the full embedded-asset allowlist for legacy wording, verify every configured skill target and opencode command, and test default output, flag variants, generated guidance, and project overrides. |
| R-18 | The embedding model is unavailable or its first download is interrupted, so the feature-enabled similarity gate cannot run. | Medium | High | Report explicit local setup guidance and fail the feature-enabled review rather than returning a false clean result; the default binary remains feature-free and ordinary no-feature workflow behavior is unchanged. |
| R-19 | A persisted index becomes stale as permanent specs change. | Medium | Medium | Store content hashes, refresh changed entries on index, and remove deleted scenarios before search. |
| R-20 | The optional fastembed build introduces a native ONNX Runtime, large model/cache footprint, possible musl/linking incompatibility, and a temporary complete-lockfile dependency-age exception. | Medium | High | Keep retrieval off by default; document the explicit lockfile-derived `GIVN_DEP_AGE_ALLOWLIST` exception authorized for this change; restore the 30-day gate before shipping a retrieval-enabled artifact; document cache setup and prove target builds. |
| R-21 | A consumer repository becomes the hidden acceptance host for Givn's own workflow. | Medium | High | Keep review/archive fixtures in Givn, invoke the compiled CLI in a fresh TempDir, and remove consumer CI dependencies. |
| R-22 | The generic fixture tests only the runner and not the child CLI process. | Medium | Medium | Assert CLI exit status and stdout as primary evidence and verify a non-zero child production path in the merged coverage report. |
| R-23 | The current permanent tree already contains high-similarity pairs, so enabling a strict gate can block every subsequent change before dogfood cleanup is complete. | High | High | Run the production scoring algorithm over the current tree, resolve every candidate by deleting true duplicates or rewriting valid boundaries below `0.95`, and record the clean baseline before archiving the gate change. |
| R-24 | A model revision or later threshold change changes the candidate set and invalidates old similarity evidence. | Medium | High | Treat the threshold as fixed per binary, record model/index metadata, and require a new versioned code/plan change plus a fresh full-tree dogfood scan for any future threshold adjustment. |
| R-25 | A valid boundary remains semantically close after a reviewer records a KEEP disposition. | Medium | High | Do not accept dispositions as exceptions; require title and step rewrites until the measured score is below the fixed threshold. |
| R-26 | A relevance reranker scores related scenarios highly without actually identifying duplicates. | High | High | Calibrate against labeled duplicate and boundary pairs; do not adopt the branch based on model scores alone. |
| R-27 | Top-K embedding retrieval omits a true duplicate before reranking. | Medium | High | Measure recall at K=5 and K=10 against known pairs; increase K or retain a deterministic fallback if recall is insufficient. |
| R-28 | CPU cross-encoder inference makes every review too slow for local authoring. | High | Medium | Bound candidate count, batch documents per query, cap ONNX threads, record latency, and compare a smaller multilingual model before adoption. |
| R-29 | Raw reranker logits are mistaken for calibrated probabilities or compared to the old embedding threshold. | Medium | High | Report raw logits and diagnostic sigmoid separately; keep the reranker boundary binary-fixed and calibrate it from labeled measurements. |
| R-30 | A query file path is normalized differently from the permanent index path, so the exact own scenario is either shown or an unrelated candidate is removed. | Medium | High | Normalize project-relative paths in one retrieval helper, test same-file identity filtering, and keep stdin identity-free. |
| R-31 | Index refresh diagnostics leak into JSON and make an otherwise valid machine-readable response unparsable. | Medium | Medium | Return refresh metadata to the renderer instead of printing it unconditionally; test that JSON stdout parses as one document. |

| R-10 | Overlap-disposition volume on the project's own tree makes the review gate self-blocking. | Medium | Medium | The gate requires dispositions only for shape matches **without** fact contradiction involving the change's delta; exit-code contrasts (0/2/3) are contradictions and only emit hints. The change itself measures its own volume (`givn check review` lists every missing row) and generates review.md from the gate output. Consequence of ADR-037 (fingerprint) — see chapter 9. |

| D-6 | `givn new` checks "change already exists" before "givn/ not found"; the already-exists branch is unreachable when `givn/` is absent (its parent cannot exist). Impact bounded as of change `fix-archive-merge-docstrings`. |
