# 11. Risks and Technical Debt

This chapter distinguishes implemented safeguards from open limitations. A
historical measurement is not a current quality claim.

## 11.1 Risks

| D-24 | The outline report has no stored classification, so every run reclassifies with the current rules and no run can be compared with an earlier one. A rules-version change silently changes what a metric hint means. | This is the deliberate price of having no baseline: there is no stale watchlist to curate and no frozen rules version. | Add a reviewed comparison only if trend evidence becomes necessary; until then `rules_version` plus the current report are the record. |
| D-25 | The advisory report's usefulness is judged manually: there is no feedback ledger or aggregate trend, only the reports the team chooses to keep. | No product state is added by decision; the report remains a read view. | Evaluate usefulness from actual REFACTOR and review use; add aggregation only if a real need appears. |
| D-26 | The report cannot judge whether a package's responsibility or call order is well designed; that remains a human source-confirmed judgment. | The tool is deterministic and offline by design. | Keep the REFACTOR and review questions authoritative; no semantic model is added. |
| D-27 | The outline is a per-component call tree, not a project call graph: same-package calls nest, calls to another component are tagged leaves, and callers are never printed. | This keeps each package's evidence independent and avoids a reverse index and cross-component expansion; the reader follows a leaf into the target component. | Add a reverse view only if source confirmation cannot reconstruct callers; no evidence for it yet. |
| D-28 | The advisory `e2e` dependency-edge finding reads Cargo manifests only, so a project whose package graph is defined by npm, NuGet, or another ecosystem receives no edge finding. | The finding is advisory and the limit is documented in the use-case contract and `docs/reference.md`; reading one manifest format statically keeps `givn lint` free of project toolchain invocation. | Add a manifest reader per ecosystem only if a non-Cargo project enables `ise` and relies on the finding; until then the absence is stated rather than inferred. |
| D-29 | The stack extraction and the corpus cap pull in opposite directions: moving rows is line-neutral, so the cap is met by deleting duplicated guidance, and a future runner now costs a file header inside the same ceiling. | The deleted text is duplication of a policy another instruction owns, and the split rule (`ADR-077`) makes the remaining owners explicit; the ceiling is a recorded constant with two asserted conditions, so raising it is a visible spec change. | Add a stack file only with the consolidation that pays for it; negotiate the ceiling in its own change if a real guidance need cannot fit. |

## 11.4 Resolved Boundaries

- Active change ids are validated as lowercase ASCII kebab-case before the
  shared change path is constructed.
- Givn does not overwrite user content outside its own `AGENTS.md` fenced blocks.
- The semantic retrieval engine (local E5 retrieval, BGE/NLI evidence,
  model-cache acquisition, and the semantic review gates) was removed by the
  `drop-embedding-features` change; ADR-069 records the single feature-free
  binary without model dependencies. The engine risks and debts formerly
  tracked here (model download, tokenizer caps, semantic review debt, and the
  feature-matrix churn) are resolved by that removal.
- The in-tool history rewrite was retired by the `drop-legacy-residue` change:
  the rules boundary is report-only end to end, and the capability is recorded
  in `givn/specs/.retired.yaml`. The 1.0 baseline later removed the remaining
  pre-1.0 migration routes and guides; the shipped catalog is empty and retired
  configuration requires the documented manual transition.
- The generated config scaffold was brought back in line with the embedded
  manifest by the `drop-legacy-residue` change: the project-level addon keys
  nest under `addons:`, the mandatory-check contract replaced the stale
  `tasks.post`/`review.post` defaults, the arc42 section states the fixed
  `docs/arc42/` path, and the placeholder repository URL is corrected. Debt
  D-3 is repaid and removed from the debt table; R-7 remains only for
  already-generated configs until their next `givn upgrade`.
