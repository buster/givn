# 11. Risks and Technical Debt

This chapter distinguishes implemented safeguards from open limitations. A
historical measurement is not a current quality claim.

## 11.1 Risks

| ID | Risk | Likelihood | Impact | Mitigation / current boundary |
|---|---|---:|---:|---|
| R-1 | Replaced scenarios cannot preserve every original docstring delimiter detail. | Medium | Medium | The text-level merge preserves content and tables but renders replacement docstrings from the parsed AST. |
| R-2 | Overlay semantics are misunderstood. | Medium | High | Artifact patches deep-merge by id; top-level `verify`, `coverage`, and `apply` overlays replace blocks. Keep the effective-manifest order documented. |
| R-3 | Static native linking is not proven for every target. | Medium | High | Treat musl, Windows, and release artifacts as unverified until built. |
| R-4 | Users assume Givn owns all of `AGENTS.md`. | Medium | High | Givn owns only its matching fenced blocks; all surrounding content is user-owned and must be preserved. |
| R-5 | A failed archive is mistaken for a completed publication, or its candidate state is lost. | Low | Critical | The candidate commit and pending receipt are written before verification; only a reconciling result set plus an evidence-only finalization commit completes the archive, and a failed candidate is resumed in place. |
| R-6 | Arc42 documentation becomes stale or is treated as a generated copy. | Medium | High | Arc42 completion review compares durable chapters, change assessment, design, tasks, and implementation; integrity checks resolvable affected files against templates, while missing files remain a current helper gap. |
| R-7 | Generated config comments describe old post-hook defaults or nonexistent Arc42 settings. | High | Medium | The runtime contract is the current embedded manifest and source: standard post lists are empty, mandatory checks are binary-owned, and Arc42 output is fixed. |
| R-8 | E2E detection misses scenarios nested under `Rule:` because the current helper checks direct feature scenarios only. | Medium | High | Keep the limitation explicit in review and add coverage before treating nested E2E detection as complete. |
| R-23 | Ordinary design, process, or implementation choices inflate the active ADR contract. | High | High | Apply the strict five-dimension AND gate plus the three falsification tests, reject shared-guidance-only claims, require the cheaper-home challenge for every proposed `NEW_ADR`, and route each non-ADR decision to exactly one canonical artifact. |
| R-24 | ADR consolidation loses unique rationale, relationships, or ownership. | Medium | High | Use the complete ID-by-ID disposition manifest, preserve only genuine superseded architecture history, and review every target link and canonical source before removing a record. |
| R-25 | The qualification procedure drifts between the canonical addon instruction and derived design-review guidance. | Medium | High | Keep the complete procedure and MADR template in one source, make derived assets thin, and verify effective/generated guidance parity. |
| R-26 | Authors treat the LLM verdict as machine-enforced architecture validation. | Medium | High | State the non-runtime boundary explicitly and require human/design-review evidence; the current integrity hooks do not infer architectural significance. |
| R-27 | Automatic upgrade commits a generated file that a project has treated as user-owned. | Medium | High | Require a clean worktree, stage an explicit known-path allowlist, preserve ejected facets, and expose both commit diffs for review. |
| R-28 | Commit A succeeds but Commit B fails, leaving the generated migration plan uncommitted. | Low | High | Never reset history; keep the plan visible, report the successful hash and remaining files, and make rerun behavior preserve the existing plan. |
| R-29 | A project interprets `givn_config_version: 0.3.0` as proof that semantic migration is complete. | High | High | Create the visible maintenance change, record the distinction in its design, and require normal LLM review/archive completion. |
| R-30 | A future migration catalog contains a broken edge or incomplete bundle and leaves a version gap unclear. | Medium | High | Validate schema, unique IDs, advancing versions, referenced assets, ordered paths, and fail explicitly once a declared route has started. |
| R-31 | Multiple required bundle phases are treated as independent concurrent changes. | Medium | High | Materialize one aggregate maintenance change with `migration.yaml`, explicit sequence numbers, and prompts that require strict phase order. |
| R-33 | Force-staging an ignored managed path could accidentally include unrelated user content. | Medium | Critical | Resolve individual managed paths before staging, force only under the `versioned` policy, never stage directories or `AGENTS.md`, and retain the clean-worktree preflight. |
| R-41 | The ephemeral port allocated for a `port_env` product is claimed by another process between givn's bind-0 probe and the child's bind (TOCTOU). | Low | Medium | Accept the narrow race; givn reports the child's early exit or the readiness timeout instead of silently retrying allocation, and the ready line names the actual port. |
| R-42 | `givn run` signal forwarding is unix-only; a Windows host running a server product gets a preflight refusal, which may surprise cross-platform projects. | Medium | Medium | The refusal is explicit at preflight with exit 1 and a named platform constraint; cli/library products work everywhere; the constraint is documented in the template and specs. |
| R-43 | A project declares `product_type: library` to escape the server requirements (declaration spoofing). | Medium | Medium | Deliberately uncountered inside givn: a heuristic would guess and block on guesses. The declaration is versioned and README-rendered, so a wrong entry is visible in review, and the caller's preview gate treats a falsified entry as an obviously wrong record, not a green start. |
| R-44 | Signal forwarding reaches only givn's direct `sh -c` child; grandchildren of compound start commands (`a && b`, pipelines) survive the interrupt. | Medium | Medium | Documented residual (unix-boring tradeoff): start commands should use `exec` so the shell process is replaced by the product; givn does not reimplement process-group supervision, and the trap-marker teardown scenarios cover the direct child. |
| R-45 | The `givn run` machine contract (ready line format, exit codes, signal behaviour) becomes a durable public compatibility obligation once it ships; breaking it breaks kiekste and caller scripts. | Medium | High | The contract is pinned by executable specs — the `run-execution` @e2e ready-line/exit-code scenarios and the spec'd exit-code table; changing any of these surfaces requires a spec change, which is visible in review. |
| R-46 | Ideation topic state (`givn/ideation/`) and promoted personas (`givn/personas/`) are agent-written conventions with no binary validation; a drifting or malformed state silently degrades resume and handoff. | Medium | Medium | The generated skill's contract phrases (phase ladder, persona rules, state paths, handoff safety) are executable-spec asserted at every `skills sync`; change-seed status lines and persona references additionally get advisory `givn lint` checks, and the review gate resolves a visual change's `PERSONAS:` ID against the project collection; state-file structure itself stays convention and is reviewed at handoff, not machine-enforced. |
| R-47 | A semantic migration can misclassify a mixed domain area as one use case or fragment. | Medium | High | Require a confirmed mapping ledger, stable behavior hashes, explicit operations, and no semantic move without user confirmation. |
| R-48 | A use-case narrative can be replaced from a stale active change. | Medium | Critical | Record a base SHA-256 revision and reject stale replacement before archive mutation; back up narratives with feature files. |
| R-49 | A release can claim semantic migration completion without retained Givn self-migration evidence. | Medium | High | Require executable migration-gate scenarios, before/after receipts, a complete ledger, and a concrete release target before publishing the bundle. |
| R-50 | OpenCode changes the plugin contract and model attribution becomes partial without a compile-time error. | Medium | High | Read the documented session, tool, and shell hook payloads defensively, keep missing metadata non-blocking, and execute the generated plugin against the simulated contract in the attribution E2E scenario. |
| R-51 | Claude changes transcript record shape or records model changes asynchronously, causing the hook to use a stale or unavailable model. | Medium | High | Read the latest assistant record defensively, retain environment fallbacks, and execute the generated hook with a real transcript fixture and Git commit regression scenario. |
| R-52 | A shell wrapper such as RTK drops a command-prefix environment and the Git hook receives no attribution context. | Medium | High | Export context for the complete Bash command and keep the Git hook responsible for consuming process-scoped variables; exercise compound command execution through the Claude regression scenario. |
| R-53 | The archive-proof guarantee assumes permanent specs only change through proven archives; a direct edit or legacy archive would leave a green corpus claim without a receipt. | Medium | High | The archive is the only writer of permanent specs, legacy archives are refused re-publication, and status surfaces unproven candidates; the guarantee is explicit, not inferred from file presence. |
| R-54 | Review loses fresh instrumented coverage data until the archive receipt exists, weakening review-time classification. | High | Medium | Review classifies from the most recent available evidence and static inspection; the archive receipt is the durable execution and coverage proof, and the review instruction records the boundary. |
| R-55 | An automated candidate or finalization commit is rejected by a user commit hook, leaving a staged tree that the developer must resolve. | Low | Medium | Normal commits run hooks; a rejection is reported as an unproven staged tree with the Git error and the forward-repair instruction, never as a successful archive. |
| R-56 | Visual review drifts into subjective pixel or taste judgments and blocks conforming work. | Medium | Medium | The contract is style-level; the review guidance forbids pixel-level and coordinate findings; an improvement inside the contract updates the contract, and a taste note without a failed persona goal is recorded but not blocking. |
| R-57 | Committed visual evidence bloats the repository over many changes. | Medium | Low | Only the final-state screenshot per `@e2e` scenario and viewport plus the evidence for states the contract declares is committed; per-assertion captures stay ephemeral under `reports/`. |
| R-58 | The persona vision review cannot run on a non-vision harness and silently degrades. | Medium | High | The verdict is recorded as `VISUAL-REVIEW: UNVERIFIED`, which blocks review until a human signs off; the gate never accepts a silent pass. |
| R-59 | A change visibly adds a screen but omits the visual contract to bypass the gate. | Medium | High | The design instruction mandates the contract for new or visibly changed screens; the review fabrication audit checks the omission, and the review instruction names it as a finding. |
| R-60 | The persona requirement is satisfied by a `PERSONAS:` marker without a real operator confirmation. | Medium | High | The design-review grilling asks the operator and records the confirmation; the marker is the durable record, and the review instruction requires the operator confirmation for a reasoned none. |
| R-61 | A deferral is kept out of `review.md` to avoid the operator decision the gate requires. | Medium | High | The review and design-review instructions name undeclared deferrals as findings; the fabrication audit checks that a mandatory check was not silently weakened. |
| R-62 | Per-state evidence grows the committed evidence set for every declared state. | Low | Medium | Only states the contract declares are required; intermediate captures stay under `reports/`, and the contract owner chooses the state list. |
| R-63 | A project root carrying both a Git marker and a Fossil marker is refused as ambiguous, and this version offers no config override to force a backend. | Low | Medium | The refusal names both markers, so the fix is visible; removing the stray marker is the only route, and a forced-backend key can be added later if mixed setups justify it. |
| R-64 | Backend detection depends on external executables: a nested project without a `.git` entry at its root and without `git` on PATH is reported as having no version control rather than as a missing tool. | Low | Low | The missing-executable refusal fires whenever the marker is present at the root; the residual case is documented here and does not mutate anything. |
| R-65 | Witness-bounded publication commits the whole dirty set on Fossil: a future caller that publishes without the clean-state witness would include unrelated changes. | Low | High | `Backend::publish` validates the exact dirty set against the resolved publication paths before recording anything, so the failure is loud rather than silent; every publishing command goes through the seam. |
| R-66 | The repository acceptance suite now depends on the `fossil` executable; a machine without it cannot run the Fossil scenarios. | Low | Medium | CI installs the distribution package and the local prerequisite is recorded in `AGENTS.md`; the scenarios fail loudly with a missing executable rather than skipping. |
| R-67 | A startup, skill, command, or delegated context omits the effective dialog obligation or restates a competing policy. | Medium | Medium | The full policy has one canonical owner. The pending decision-ready-question change broadens bundled entry-point references and explicit delegation handoff; review must still identify competing local wording. |
| R-68 | A term is confirmed without a real collision check ("no collision" with no recorded commands), and the collision surfaces only when a user challenges the vocabulary mid-ideation. | Medium | Medium | The term record requires the pasted commands and hit counts before `confirmed`; the ideation quality review verifies recorded checks, and Handoff proposes only confirmed terms for the durable glossary. |
| R-69 | Capability absorption continues where reviewers are lax: the use-case scoping rules are prose, and the only size signal still punishes small leaves. | Medium | Medium | Each rejection criterion names the observable document section that proves it, so review is mechanical rather than tonal; the structural router/parser fix is deliberately deferred and recorded as accepted risk. |
| R-70 | The qualifier and the ledger are prose: a use case can still promise a guarantee while its prerequisite is open, and a proposal can still defer with "resolved in design.md". | Medium | Medium | The qualifier is a grep-able marker referenced from the review criteria, the disposition rule names the three valid outcomes, and design-review verifies every `D<n>`; the hard requirement is scoped to ideation-sourced changes to avoid bureaucratic overhead. |
| R-71 | Route confidence thresholds are miscalibrated: too high and useful nudges disappear, too low and ranking noise returns. | Medium | Medium | The rules reuse the existing extend bar and a conservative affinity floor, the tie epsilon is 0.01, and the no-signal verdict prints its reason; the deterministic fixtures cover the tie, the goal-aligned ranking, and the empty-overlap case. |
| R-72 | A scripted `givn init` that relied on the implicit OpenCode default now exits non-zero until it states a selection. | Medium | Low | The refusal names `.opencode`, `.agents`, `.claude`, and the `--agents` flag, and it happens before the first write, so the project is unchanged and the rerun with `--agents` is the fix; the amendment is recorded in ADR-013 and chapter 8.7. |
| R-73 | Complete-looking policy references or formatted options are mistaken for informed consent or proof of agent compliance. | Medium | High | The pending contract separates real-interface distribution evidence from unseen fresh-context review; inspect actual decision contents and consequences and reject invariant-violating options. No model score or runtime gate guarantees question quality. |
| R-74 | A project-owned instruction, skill, or command override stays on old question guidance after synchronization. | Medium | Medium | Preserve the cascade and user ownership; the owner reviews the effective replacement. Do not silently inject defaults into overrides or claim sync upgrades them. |
| R-75 | The changelog's exact-subject dedupe merges two changes whose release notes are identical, and its per-group application lists one change once per group when its revisions carry mixed subject types. | Low | Medium | Every revision of a change shares the release note as its subject, so both cases are convention violations; the filter matches the subject exactly (`case_sensitive=true`), the generated section is visible in the release run, and the limitation is registered here. |
| R-76 | The release base guard refuses every release until the package version carries a matching version tag; after the 0.7.0/0.8.0 tag deficit the next release needs the one-time `v0.8.0` tag. | Medium | Low | The guard names the missing tag and stops before any mutation; the one-time tag is a recorded rollout step in the release-truth design, and no release can silently reuse an older range. |
| R-77 | The generated omp hook only rewrites Bash commands whose text names a revision verb, so a revision created through a spelling that omits it (for example `git merge --no-edit` or `git cherry-pick`) records no LLM attribution. | Low | Low | The gate keeps the export prefix out of every other persisted tool call; the accepted limitation is recorded in the change design and in chapter 6.1a, and it degrades to an ordinary commit rather than a failed one. |
| R-78 | The generated omp hook relies on the documented omp extension contract (`<cwd>/.omp/hooks/pre/*.js` factory, `tool_call` event with an `input` rewrite, `ctx.models`, `pi.getThinkingLevel`); the automated E2E fakes that contract, so it validates the generated artifact but cannot detect a drift in omp itself. | Low | Medium | The contract was validated end to end against a real omp 18.3.0 session on 2026-10-05: the hook rewrote the command, the checked-in hook stamped the commit, and the result carried `LLM: deepseek/deepseek-flash via omp` and `Co-Authored-By: deepseek/deepseek-flash/high@omp with Givn 0.8.3`. The E2E keeps faking the context so the suite stays credential-free; a future omp release that changes the contract degrades to ordinary unattributed commits rather than a failed commit, and the live smoke run is the repeatable check. |

## 11.2 Deliberate Technical Debt

| ID | Debt | Current state | Repayment |
|---|---|---|---|
| D-1 | No `givn migrate` from OpenSpec. | Clean break is current. | Add an explicit reviewed migration command if demand justifies it. |
| D-2 | Release binaries, Homebrew, shell installer, target matrix, and `cargo publish` are not wired in this checkout. | The GitHub release channel is wired by the single release workflow, which publishes from the generated changelog section; these channels remain planned. | Implement and verify each channel before claiming it. |
| D-3 | Generated config comments can lag the embedded runtime manifest. | `commands.yaml` and mandatory-check behavior moved ahead of older comments. | Update the asset template in a separate code change; durable Arc42 docs describe runtime behavior, not stale comments. |
| D-4 | `givn new` writes the proposal template verbatim, including its literal placeholder. | Characterized behavior. | Add a reviewed delta to substitute or remove the placeholder. |
| D-5 | `givn new` checks existing change before missing `givn/`, making one branch unreachable in practice. | Characterized behavior. | Reorder checks in a reviewed change if the error distinction matters. |
| D-6 | Natural `givn new -foo` is rejected by `clap`, while `givn new -- -foo` reaches the id validator. | Characterized behavior. | Unify the two input paths if a consistent diagnostic is required. |
| D-7 | `givn init` does not create `givn/artifacts/` proactively. | Eject can create needed parent paths, but the directory is absent initially. | Add explicit scaffolding or improve eject guidance. |
| D-8 | Replaced scenario docstrings may lose delimiter/content-type formatting. | Content is retained; source delimiter style is not. | Carry source block formatting in a future merge change. |
| D-9 | Rule-nested WIP/E2E checks use existing direct-scenario traversal limits. | Current parser helper limitation. | Extend traversal and add regression coverage. |
| D-13 | ADR qualification is guidance-level and the register has no semantic validator. | The LLM/author and design review apply the policy; runtime integrity checks only verify mechanical file conditions. | Add a reviewed semantic register validator only if a future requirement justifies runtime enforcement; until then retain explicit review evidence. |
| D-17 | The README legacy-matcher list hard-codes the previous scaffold's placeholder sentences. | Detection is exact-text with no false positives, but a future scaffold-text change must keep the list in sync. | Update the matcher list whenever the scaffold template's wording changes, verified by the readme-enforcement scenarios. |
| D-18 | The visual gate checks the verdict marker and evidence presence; the baseline assertion quality and the persona vision judgment are guidance-level. | The binary cannot infer whether a screenshot is good or whether a project's e2e steps really assert the baseline. | Keep the review fabrication audit authoritative; add semantic checks only if a future requirement justifies runtime enforcement. |
| D-19 | The state-evidence check is per declared state and viewport across the change, not per traversing scenario; the persona marker records a disposition, not a verified operator sign-off. | The binary cannot know which scenario traverses which state, and it cannot verify a conversation. | The guidance states the per-scenario intent and the design-review grilling records the sign-off; add runtime enforcement only if a future requirement justifies it. |

## 11.4 Resolved Boundaries

- Active change ids are validated as lowercase ASCII kebab-case before the
  shared change path is constructed.
- Givn does not overwrite user content outside its own `AGENTS.md` fenced blocks.
- The semantic retrieval engine (local E5 retrieval, BGE/NLI evidence,
  model-cache acquisition, and the semantic review gates) was removed by the
  `drop-embedding-features` change; ADR-069 records the single feature-free
  binary without model dependencies. The engine risks and debts formerly
  tracked here (model download, tokenizer caps, semantic review debt, and the
  feature-matrix churn) are resolved by that removal.
