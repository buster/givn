# 11. Risks and Technical Debt

## 11.1 Risks

| ID | Risk | Likelihood | Impact | Mitigation |
| --- | --- | --- | --- | --- |
| R-1 | The `gherkin` crate's AST does not expose enough position info to losslessly merge + strip tags while preserving formatting. | Medium | High | **Resolved (Phase 3):** merge operates on a line-based text model, not a full AST rewrite. This preserves formatting and comments correctly. |
| R-2 | Overlay/patch semantics for the manifest become ambiguous (deep-merge edge cases). | Medium | Medium | **Resolved (Phase 2):** overlay rules specified and unit-tested for add/modify/remove/cycle/dangling-requires. |
| R-3 | `serde_yaml_ng` diverges or is itself abandoned. | Low | Medium | Thin wrapper around (de)serialisation; `serde_norway` is a fallback fork. |
| R-4 | Skill/agent conventions shift (the `.agents/skills` convention is emerging, not ratified). | Medium | Low | Templates are ejectable and targets are pluggable; adding/altering a target is cheap. |
| R-5 | Cross-platform static linking (musl, Windows) causes build friction. | Medium | Medium | Use `cargo-dist`; pin toolchains; test in CI before first release. |
| R-6 | Merge corrupts the permanent spec on a partial failure. | Low | High | All-or-nothing archive: validate every precondition before any write; write atomically. |
| R-7 | Scope creep back toward OpenSpec's dropped features (profiles, context stores). | Medium | Medium | Chapter 3.3 non-goals are explicit; keep them out of v1. |
| R-8 | Filesystem-derived state misreads partially-written or manually-edited dirs. | Low | Medium | Derive conservatively; treat ambiguous states as "in progress"; never auto-destroy on inference. |
| R-9 | Path traversal in `--change` parameter (e.g. `--change "../etc"`). | Low | High | **Resolved:** every command that accepts `--change` now validates the id as kebab-case via the shared `resolve_change_dir` helper before constructing any filesystem path. Invalid ids are rejected with a clear error. |
| R-10 | Durable Arc42 chapters become stale, or implementation silently diverges from documented architecture after design-review. | Medium | High | When the `arc42` addon is enabled, completion review independently cross-checks Arc42 facts and affected chapters against `design.md`, `tasks.md`, and implementation evidence; mismatches block sign-off. |
| R-11 | The prompt-layer conformance review is completed superficially or omitted because the binary does not parse architecture facts. | Medium | High | Require `ARC42 CONFORMANCE: CLEAN` and a completed evidence table in the review assets; design-review and the review instructions state that any unresolved row prevents human sign-off. |
| R-12 | Existing projects that previously synced all three agent targets silently narrow to opencode after upgrade, orphaning stale `.agents`/`.claude` files. | Medium | Low | Config default is opencode-only; projects wanting all three add `skills: { targets: [opencode, agents, claude] }`. Addon `disable` still cleans all three targets so stale files can be removed. |
| R-13 | A project merge script succeeds without replacing an old merged report, publishing stale README values. | Medium | High | Archive removes the configured output before running `coverage.merge_command` and rejects a successful command that does not recreate it. |
| R-14 | E2E and non-E2E reports use different scopes or a project script merges counters incorrectly, making badges look authoritative when they are not. | Medium | High | Scripts are project-owned and documented in the README; givn validates both source reports and the fresh merged report, while review maps every instrumented production process and classifies invalid measurement as a fabrication finding. |
| R-15 | A zero branch denominator is rendered as `0%`, implying measured branch coverage where the tool emitted no branches. | High | Medium | Render `n/a` for `branches-valid=0` in the badge and summary, while preserving the raw `0/0` counters. |
| R-16 | Coverage or README updates partially succeed before a later archive gate fails, leaving user content or reports changed. | Low | High | Back up README and configured coverage paths before measurement and restore them together with permanent specs on every coverage error. |
| R-17 | Authors follow different E2E policy wording depending on the entry point used, reintroducing duplicate or under-covered interactions. | Medium | High | Keep the complete policy in the `specs` instruction; scan the full embedded-asset allowlist for legacy wording, verify every configured skill target and opencode command, and test default output, flag variants, generated guidance, and project overrides. |
| R-18 | The embedding model is unavailable or its first download is interrupted, so the `spec-similarity-gate` strict gate cannot run. | Medium | High | Report explicit local setup guidance and fail the feature-enabled review rather than returning a false clean result; `spec-retrieval` alone remains advisory, the default binary remains feature-free, and ordinary no-feature workflow behavior is unchanged. |
| R-19 | A persisted index becomes stale as permanent specs change. | Medium | Medium | Store content hashes, refresh changed entries on index, and remove deleted scenarios before search. |
| R-20 | The optional fastembed build introduces a native ONNX Runtime, large model/cache footprint, possible musl/linking incompatibility, and a temporary complete-lockfile dependency-age exception. | Medium | High | Keep retrieval off by default; document the explicit lockfile-derived `GIVN_DEP_AGE_ALLOWLIST` exception authorized for this change; restore the 30-day gate before shipping a retrieval-enabled artifact; document cache setup and prove target builds. |
| R-21 | A consumer repository becomes the hidden acceptance host for Givn's own workflow. | Medium | High | Keep review/archive fixtures in Givn, invoke the compiled CLI in a fresh TempDir, and remove consumer CI dependencies. |
| R-22 | The generic fixture tests only the runner and not the child CLI process. | Medium | Medium | Assert CLI exit status and stdout as primary evidence and verify a non-zero child production path in the merged coverage report. |
| R-23 | The current permanent tree already contains high-similarity pairs, so enabling a strict gate can block every subsequent change before dogfood cleanup is complete. | High | High | Run the production scoring algorithm over the current tree, resolve every candidate by deleting true duplicates or rewriting valid boundaries below `0.95`, and record the clean baseline before archiving the gate change. |
| R-24 | A model revision or later threshold change changes the semantic candidate set and invalidates old evidence. | Medium | High | Keep the semantic-report boundary at the existing binary-fixed E5 `0.9500`; record model/index and schema metadata in full endpoint evidence; require a new versioned code/plan change plus fresh evidence for any future threshold or model adjustment. |
| R-25 | A valid boundary remains semantically close after a reviewer records a KEEP disposition. | Medium | High | Do not accept dispositions as exceptions; require title and step rewrites until the measured score is below the fixed threshold. |
| R-26 | A relevance reranker scores related scenarios highly without actually identifying duplicates. | High | High | Calibrate against labeled duplicate and boundary pairs; do not adopt the branch based on model scores alone. |
| R-27 | E5 candidate generation omits a true duplicate before semantic-report classification. | Medium | High | Measure recall against known pairs; keep the binary-fixed `0.9500` boundary and candidate scopes explicit; do not treat this PR3 report as a full permanent audit, and defer BGE/NLI or other recall changes to later slices. |
| R-28 | CPU cross-encoder inference makes every review too slow for local authoring. | High | Medium | Bound candidate count, batch documents per query, cap ONNX threads, record latency, and compare a smaller multilingual model before adoption. |
| R-29 | Raw reranker logits are mistaken for calibrated probabilities or compared to the old embedding threshold. | Medium | High | Report raw logits and diagnostic sigmoid separately; keep the reranker boundary binary-fixed and calibrate it from labeled measurements. |
| R-30 | A permanent index file, delta source, projected target, or query file is normalized differently, so a self-scenario is shown or an unrelated candidate is removed. | Medium | High | Route every identity through one project-relative forward-slash helper that accepts relative and absolute inputs; test added self-identity, modified source/target identity, and path-form parity. |
| R-31 | Index refresh diagnostics leak into JSON and make an otherwise valid machine-readable response unparsable. | Medium | Medium | Return refresh metadata to the renderer instead of printing it unconditionally; test that JSON stdout parses as one document. |
| R-32 | A rejected change-aware request refreshes the permanent index before discovering an unsafe id, missing change/specs directory, or malformed delta, leaving persistence changed despite failure. | Medium | High | Validate the change and collect/parse all delta files before the refresh; regular executable scenarios snapshot the index and assert no mutation for every rejection boundary. |
| R-33 | Consumers interpret additive `scope`/`change` metadata as a byte-for-byte compatibility break or reject unknown JSON fields. | Medium | Medium | Document the contract as additive rather than byte-for-byte; preserve PR 1 field values and relative order, add metadata after them, and cover both text and JSON consumer interactions. |
| R-34 | A stale semantic classification is carried forward after any candidate identity or endpoint-evidence component changes. | Medium | High | Carry only when the candidate id and both complete endpoint evidence hashes match exactly; include title, all steps, background, tables, operation, projected target, content hash, model/index, fingerprint/evidence schema, and report schema in the evidence; treat new, changed, or malformed prior entries as `UNCERTAIN` and block the gate. |
| R-35 | An agent edits the change-local generated semantic report into an invalid or incomplete state and assumes the change is reviewed. | Medium | High | Regenerate the complete report on every check; parse only the strict grammar and five exact classification values; discard missing, invalid, duplicate, stale, and structurally malformed prior entries; recompute status/count and atomically write the complete report before blocking. |
| R-36 | Users mistake the change-local semantic worklist for a full permanent-corpus audit, or assume an index refresh persisted delta evidence. | Medium | High | State the explicit E5 `0.9500` candidate scopes in the report and durable docs; exclude removed and permanent-permanent pairs intentionally; assert the persisted index remains structurally permanent-only with no delta vectors, classifications, or report state. |
| R-37 | The dedicated blocking report gate is perceived as permission for Givn to classify or remediate feature files automatically. | Low | High | Keep classification and all feature-file edits agent-owned; record E5/Fingerprint evidence only, use no BGE/NLI classifier, and assert feature-file, permanent-spec, review/disposition, and index-boundary non-mutation in regular scenarios. |
| R-38 | A build without `spec-retrieval` or an unavailable retrieval model falsely passes semantic review or leaves misleading report state. | Medium | High | Route the blocking check path through the dedicated feature-gated entrypoint; return the existing retrieval-unavailable error, exit non-zero, and create no semantic report; cover both no-feature and unavailable-model fixtures. The separate strict similarity gate requires `spec-similarity-gate`. |
| R-39 | Historical semantic evidence is lost or mistaken for a permanent specification during archive. | Low | Medium | Keep report generation change-local and outside lifecycle artifact state, rely on the existing whole-directory archive move to retain `semantic-review.md` under `givn/archive/<id>/`, and document that archive behavior is unchanged and the file is historical evidence only. |
| R-40 | A malformed or incompatible permanent index is treated as usable, contaminates the rebuilt catalogue, or prevents semantic review from continuing. | Medium | High | Treat the index as stale, rebuild from permanent specifications, continue report generation, and assert that the rebuilt index contains only permanent entries with no `Delta` state, delta vectors, classifications, or report state. |
| R-41 | A permissive report parser accepts reordered/unknown fields, ambiguous absent values, unstable JSON, or trailing bytes, allowing stale classifications to survive. | Medium | High | Define and enforce the exact UTF-8/LF grammar, fixed headers and field order, compact JSON serialization, `null` absence, exact score/hash formats, one final newline, and no timestamps/environment fields; reject invalid prior state and atomically replace the complete report. |
| R-42 | Different concepts use overloaded domain terms and remain high-similarity candidates, while an agent tries to dismiss them without sharpening the vocabulary. | Medium | High | Do not allow an `UNRELATED` escape classification; require vocabulary/invariant sharpening until the score falls below the boundary or require a rationale-backed `DUPLIKAT`, `VARIANTE`, or `VALID-BOUNDARY` decision, retained in the archived report. |
| R-43 | The feature-free dogfood binary cannot run the blocking semantic review and would fail review/archive after the explicit no-feature hard-fail. | Medium | High | Install the local dogfood binary with `--features spec-retrieval`, sync skills afterward, run the retrieval-enabled suite, and keep the no-feature build as a separate explicit-unavailable compatibility test. |
| R-44 | A classified candidate disappears or falls below the report threshold and is silently treated as remediated. | High | High | Keep a separate prior-entry verification path, resolve identities against the projected tree, recompute below-boundary scores, and block no-match or unsatisfied class contracts. |
| R-45 | A lower score is mistaken for a `VARIANTE` consolidation or `VALID-BOUNDARY` distinction. | High | High | Require a parameterized outline with examples for variants and a changed observable fact or condition/outcome invariant for valid boundaries; add negative score-only scenarios. |
| R-46 | The canonical specs instruction, design guidance, and review guidance disagree about the real E2E boundary. | Medium | High | Keep primary interface assertions, browser-driver fidelity, and obstacle handling in the resolved specs instruction; treat other copies as derived checks and test the effective override. |
| R-47 | Retrieval-era guidance tells enabled builds to avoid retrieval or omits the distinction between advisory authoring and blocking review. | Medium | Medium | Make guidance feature-aware, retain explicit unavailable failures for feature-free builds, and document `index`/`search`/`explore` versus `check review`. |
| R-48 | A generic review passes classification without recording class-specific semantic remediation evidence. | Medium | High | Add remediation contracts, projected-tree evidence, failure status, and the deterministic verification receipt to the generic review instruction and template. |
| R-49 | Agents parse a stale or incomplete instruction JSON contract and choose the wrong artifact path or prerequisite. | Medium | High | Emit `{id, generates, requires, instruction}` from the effective manifest/cascade, update command consumers, and assert one valid JSON document through the compiled CLI. |
| R-50 | The complete permanent duplicate audit performs an exhaustive pair scan and in-memory semantic scoring, so runtime and memory grow quadratically with corpus size. | Medium | Medium | Embed each eligible scenario once and score pairs in memory. Record the current baseline of approximately 288 scenarios and 41,328 pairs; design a bounded/indexed approach before 500 scenarios or approximately 124,750 pairs. Keep the current result complete and advisory until then. |
| R-51 | Local E5 candidate recall and precision may miss true semantic duplicates or produce noisy advisory candidates, and users may mistake a score for an automatic duplicate decision. | Medium | High | Measure true positives, false positives, false negatives, precision, and recall against labeled duplicate, structural, boundary, and unrelated pairs at `0.9500`. Keep semantic candidates advisory, never classify automatically, and never suppress deterministic Fingerprint evidence. |

| R-10 | Overlap-disposition volume on the project's own tree makes the review gate self-blocking. | Medium | Medium | The gate requires dispositions only for shape matches **without** fact contradiction involving the change's delta; exit-code contrasts (0/2/3) are contradictions and only emit hints. The change itself measures its own volume (`givn check review` lists every missing row) and generates review.md from the gate output. Consequence of ADR-037 (fingerprint) — see chapter 9. |
