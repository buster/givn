in `trial-revision.txt`. A setup failure is not a `Spec gap`; each difference
between the frozen `@e2e` result and the rebuilt binary receives exactly one
outcome under `## Spec gaps`.

## Trial count reconciliation

`givn spec coverage --format json` reports 115 selected `@e2e` definitions and
56 distinct feature paths. The frozen runner expands Scenario Outlines per
example and reports 120 scenarios: the 115 definitions plus 5 examples from
three outlines (`archive-proof`, `agent-activity-reporting`, and
`development-report`; the inventory names them). The baseline run on
2026-11-17 against the checkout binary recorded `total` 120, `passed` 120,
`failed` 0, `skipped` 0. The trial uses 120 as the runner total; the inventory
row count stays 115 definitions. This is a count-semantics difference, not a
`Spec gap` outcome.

```sh
GIVN_BIN=/tmp/givn-ise-self-rebuild-20261117T133311Z/target/release/givn \

```

`GIVN_BIN` is the rebuilt binary. `GIVN_READY_FIXTURE` is built by
`run-tests.sh` from the checkout's `tests/ready_fixture.rs`, and `GIVN_ROOT`
defaults to the checkout. Those two inputs are test infrastructure, not product
construction. The clean-room claim covers product behavior, not the fixture
bytes or the checkout files those repository-file assertions read.

The trial-1 triage table's observed column escapes `|` as `\|`; a column count
that does not account for the escape sees extra fields on three rows. The
outcome counts in the summary are authoritative.
