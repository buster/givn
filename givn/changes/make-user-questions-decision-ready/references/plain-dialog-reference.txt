                              Approved effective-policy direction                               

Adopt option 3: the generated AGENTS.md project guidance requires the effective dialog policy,  
and every available Givn skill and command references that same policy. The normal givn         
instructions startup guidance reinforces the obligation. The policy remains retrievable through 
givn instructions dialog, including before a change exists.                                     

The obligation is unconditional: it applies with optional addons disabled and regardless of     
workflow phase, direct skill invocation, clarification, confirmation, review, or delegation. It 
includes questions an agent asks while working in a Givn project outside a named skill. Optional
tone policies must not redefine or weaken it.                                                   

An agent loads the effective policy once per context, before its first user-facing question,    
rather than repeatedly retrieving it before every question. Direct skill guidance requires      
loading it if that context has not already done so. Delegated agents receive the same obligation
explicitly; the agent presenting a delegated question remains responsible for its quality. No   
inheritance of the parent's loaded context is assumed.                                          

Generated project guidance is refreshed through normal initialization and skill synchronization,
while unrelated human-authored guidance is preserved. Detailed rules and multi-shot examples    
live only in the effective dialog policy; project, skill, command, and delegation guidance carry
short consistent references rather than competing full policies. Existing project instruction,  
skill, and command overrides remain authoritative and are not overwritten, secretly augmented,  
or bypassed by this change. Bundled defaults supply the universal references; owners must       
reconcile stale replacement templates with the same authoring obligation. Synchronization alone 
must not be represented as updating an override.

▌ Should general collaboration rules be readable before an active task exists?                
▌ The draft rejects tool instructions dialog with No active task, which prevents an agent from
▌ reading the collaboration rules before planning. Details: the draft behavior and boundary.

                                   Example 4 decision record                                    

Hypothetical saved-project upgrade: the old format records a preview setting called Backend

                 Good — show the hard-to-change cost and its purchased benefit                  

▌ Should this terminology change include upgrading existing saved projects?                   
▌ Documentation will call the preview setting Candidate Port. We must choose whether saved    
▌ projects change with it. Details: the upgrade and compatibility record.                     
▌ Upgrade saved projects in this change. Example: a project saved as Backend Port = 8080

▌ cannot open upgraded projects. Changing course after rollout requires verified reverse      
▌ conversion, not just reinstalling the old release. Such recovery is required work, not

Hypothetical review record: a status scenario succeeds whenever the output contains the word

▌ Which of the 22 status scenarios proves nothing? Should we keep the broad substring check or
▌ choose exact whole-output matching?                                                         
▌ Alternatively, should a repeated answer become a second answer so a human can decide? The   
▌ run might continue twice.                                                                   

              Good — do the research and report; do not ask a preference question               

▌ The status check accepts an inactive project when an unrelated label contains active.       
▌ Details: the assertion counterexample and status contract.                                  
▌ I will make the assertion distinguish the actual project status while preserving the        
▌ existing output contract. The inactive-project counterexample will fail; an active project

Contrast: investigate unseen assertions instead of asking the human to memorize them; reject a  
false dilemma and an invariant-violating alternative. The policy's good outcome is sometimes a  
report with no user-facing question.
